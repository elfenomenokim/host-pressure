# Measurements, 2026-11-17

These files retain the raw runs used by the README. Three warmups and 30
measured launches were used on each platform. The default command may wait
for a CPU sample; `--no-sample` measures a different path.

- `m5-hyperfine.json` / `.txt`: Hyperfine 2.0.0, default commands, macOS arm64,
  Apple M5 Pro, Python 3.12.8, release Rust binary from this checkout.
- `m5-no-sample.json` / `.txt`: the same commands with `--no-sample`.
- `m5-{python,rust}-{time,output}.txt`: separate `/usr/bin/time -l` runs.
  Maximum resident set size is in bytes on macOS.
- `a1.json`: subprocess-loop timings and separate `/usr/bin/time -v` outputs.
  Linux RSS is in KiB. `a1-bench.py` is the exact runner, with the executable's
  home prefix expressed through `Path.home()` for reuse. The raw JSON uses
  `~/.local/bin/host-pressure` for that prefix. The Python package was already
  installed in `/tmp/hp-venv`; no package source checkout was present there.
  Architecture is aarch64; CPU model was not verified by the device spec route.
- `windows-stdout.txt` / `windows-stderr.txt`: raw PowerShell output.
  `windows.json` is the parsed copy. `windows-bench.ps1` creates a temporary
  venv, installs host-pressure 0.1.0, runs hidden child processes, then deletes
  only that newly created venv. CPU: AMD Ryzen 7 PRO 6850U with Radeon Graphics,
  observed through the device hardware query. Python uses the venv launcher.
- `windows-rss.json` / `windows-rss.ps1`: separate GetProcessMemoryInfo readings.
  These are not used in the README table: Python's venv launcher delegates to
  a child, so its own peak working set is not the full Python process footprint.
  The earlier .NET peak-working-set fields were null, also retained as observed.

Run the M5 commands printed in the README from the repository root. The A1
runner needs an installed Python package at its stated venv path; adjust the
command list for another machine. The Windows script uses `py -3`, PowerShell,
and PyPI access. Do not compare the results as an isolated CPU benchmark:
background load, filesystem caches, CPU counter timing, and launchers differ.

## No-sample comparison and A1 default diagnosis

The leading README table uses `--no-sample` on every host. M5's original
30-run no-sample timings are reused; its no-sample RSS is in
`m5-no-sample-{python,rust}-{time,output}.txt`. A1's new runs are in
`a1-no-sample.json`, generated by `a1-no-sample-bench.py`.
`windows-bench.ps1 -NoSample` adds the flag to warmups and all measured calls;
its raw output and parsed data use the `windows-no-sample` prefix.

`a1-default-diagnosis.py` compares 30 default JSON calls per edition with no
pause and with 50 ms between calls. Each edition/interval has a separate state
directory. The measured duration excludes the pause and the before/after state
reads. `a1-default-diagnosis.json` records `cpuSource` and the exact tick-delta
total for each call: every Rust sampling fallback had zero baseline tick delta.
All 30 spaced Rust calls used the baseline. Python's longer startup naturally
spaced its readings enough to observe new ticks in this run.
